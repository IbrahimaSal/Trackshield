## User Story

En tant que développeur, je veux des tests HTTP automatisés sur tous les controllers NestJS afin de valider les codes de statut, les guards JWT et les contrats de réponse sans démarrer l'app manuellement.

## Contexte

Les controllers `UsersController`, `EventsController` et `SyncController` n'ont aucun test automatisé. Les codes HTTP (201, 204, 401, 404…) et les guards ne sont vérifiés qu'à la main via curl. Le problème bloquant : Vitest utilise esbuild qui ne supporte pas `emitDecoratorMetadata`, ce qui rend `Test.createTestingModule()` inutilisable. La solution est de remplacer esbuild par SWC comme transformer Vitest (`unplugin-swc` + `@swc/core`).

## Critères d'acceptation

- [ ] `unplugin-swc` configuré dans `apps/api` — `Test.createTestingModule()` fonctionne
- [ ] Tests Supertest pour `UsersController` : POST /api/users (201, 409), GET /api/users/me (200, 401)
- [ ] Tests Supertest pour `EventsController` : POST /api/events (201, 401, 404 session inconnue)
- [ ] Tests Supertest pour `SyncController` : GET /api/sync/history (200, 401), DELETE /api/sync/data (204, 401)
- [ ] Les repositories sont mockés — aucun accès base de données réelle dans ces tests
- [ ] `pnpm test` reste vert — les tests service existants (instanciation directe) continuent de passer

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer / modifier :**
- `apps/api/vitest.config.ts` — configurer `unplugin-swc` comme transformer
- `apps/api/src/__tests__/users.controller.spec.ts` — tests HTTP UsersController
- `apps/api/src/__tests__/events.controller.spec.ts` — tests HTTP EventsController
- `apps/api/src/__tests__/sync.controller.spec.ts` — tests HTTP SyncController

**Setup SWC :**
```bash
pnpm add -D @swc/core unplugin-swc --filter @trackshield/api
```

```typescript
// apps/api/vitest.config.ts
import swc from 'unplugin-swc'
import { defineConfig } from 'vitest/config'

export default defineConfig({
  plugins: [swc.vite({ module: { type: 'es6' } })],
  test: { globals: true },
})
```

**Pattern Supertest avec module minimal (pas de DB) :**
```typescript
const mockUsersService = { createUser: vi.fn(), findById: vi.fn() }

const moduleRef = await Test.createTestingModule({
  controllers: [UsersController],
  providers: [{ provide: UsersService, useValue: mockUsersService }],
}).compile()

const app = moduleRef.createNestApplication()
app.useGlobalPipes(new ValidationPipe({ transform: true, whitelist: true }))
app.setGlobalPrefix('api')
await app.init()

// puis : request(app.getHttpServer()).post('/api/users').send({...})
```

**Pour les routes protégées par JwtAuthGuard :**
- Override le guard avec un guard qui injecte un user fictif → tester le comportement 200/204
- Tester sans token → vérifier 401

**Patterns à respecter :**
- Modules minimaux par controller — pas de bootstrap de l'AppModule complet
- Repositories mockés avec `vi.fn()` — zéro accès DB
- `@Controller` path sans préfixe `api/` (globalPrefix géré par `app.setGlobalPrefix`)
- Fermer l'app après chaque suite : `afterAll(() => app.close())`
