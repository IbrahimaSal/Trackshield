## User Story

En tant que Marie, je veux que les alertes Trackshield correspondent à de vraies données personnelles, afin de ne pas être exposée à du bruit qui érode ma confiance dans l'outil.

## Contexte

Aujourd'hui la regex `TEL` détecte toute séquence de 10 chiffres — ce qui englobe les IDs de médias Twitter, les timestamps, les identifiants techniques. Le résultat : des dizaines de faux positifs masqués comme `0397••••4687` qui n'ont rien à voir avec un numéro de téléphone. Il faut contraindre les patterns pour qu'ils ne matchent que des données réellement personnelles dans leur forme.

## Critères d'acceptation

- [ ] La regex `TEL` ne matche que les numéros de téléphone au format reconnu : français (06/07/+33), international (+XX…)  — pas les séquences numériques arbitraires
- [ ] La regex `EMAIL` est inchangée (elle est déjà précise)
- [ ] La regex `LOC` ne matche que les coordonnées GPS réalistes (lat entre -90/+90, lon entre -180/+180)
- [ ] La regex `ID_PUB` est retirée ou limitée aux patterns d'identifiants publicitaires documentés (IDFA, GAID format UUID)
- [ ] Un jeu de tests `SHOULD_DETECT[]` + `SHOULD_NOT_DETECT[]` couvre chaque pattern (≥5 cas positifs + ≥5 cas négatifs par pattern)
- [ ] Le nombre de faux positifs sur une page Twitter type est réduit d'au moins 80%

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer / modifier :**
- `apps/plugin/src/background/pii-detector.ts` — resserrer les patterns regex avec anchors, lookahead, contraintes de contexte (séparateurs, longueur exacte)
- `apps/plugin/tests/pii-detector.test.ts` — ajouter `SHOULD_DETECT[]` + `SHOULD_NOT_DETECT[]` pour chaque pattern revu

**Patterns à respecter :**
- TDD strict : écrire `SHOULD_NOT_DETECT` avec les IDs Twitter avant de modifier les regex
- Chaque pattern modifié doit avoir sa propre `describe` avec cas positifs ET négatifs
- Ne pas casser les cas existants qui passent
