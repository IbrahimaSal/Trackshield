## User Story

En tant que Marie, je veux créer un compte avec mon email afin de pouvoir activer la synchronisation cloud et retrouver mon historique sur un autre appareil.

## Contexte

Le module Users gère la création de compte et la récupération du profil. Il est nécessaire pour que le module Auth puisse valider les credentials et pour que le module Sync sache à quel utilisateur appartiennent les données.

## Critères d'acceptation

- [ ] Un utilisateur peut s'inscrire avec email + mot de passe
- [ ] Le mot de passe est haché avant stockage (bcrypt, jamais en clair)
- [ ] Un email déjà utilisé retourne une erreur 409 explicite
- [ ] Le profil retourné ne contient jamais le mot de passe haché
- [ ] Aucun `any` TypeScript ni accès Prisma direct hors du repository adapter

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer :**
- `apps/api/src/users/users.module.ts`
- `apps/api/src/users/users.service.ts` — use case : createUser, findByEmail, findById
- `apps/api/src/users/users.controller.ts` — POST /users (inscription), GET /users/me (profil)
- `apps/api/src/users/domain/user.entity.ts` — entité User (id, email, createdAt)
- `apps/api/src/users/ports/users.repository.ts` — interface IUsersRepository
- `apps/api/src/users/infrastructure/prisma-users.repository.ts` — implémente IUsersRepository via PrismaService
- `apps/api/src/users/dto/create-user.dto.ts` — class-validator : email, password

**Patterns à respecter :**
- Clean Architecture + Hexagonale : UsersService injecte IUsersRepository (port), PrismaUsersRepository est l'adapter
- Pas d'accès direct à Prisma depuis UsersService — uniquement via le port
- `class-validator` sur tous les DTOs entrants
- Hachage bcrypt dans UsersService, pas dans le controller

**Dépend de :** TS-001 — PrismaService · TS-002 — Module Auth
