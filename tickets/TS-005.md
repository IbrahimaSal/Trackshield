## User Story

En tant que Marie, je veux retrouver mon historique de détections sur un nouvel appareil afin de ne pas perdre l'historique de mes navigations précédentes.

## Contexte

Le module Sync expose les endpoints qui permettent au plugin de récupérer l'historique sauvegardé et de gérer le consentement. C'est la dernière brique de la sync cloud opt-in — elle ne sert que si Marie a activé la synchronisation depuis les paramètres (TS-011).

## Critères d'acceptation

- [ ] `GET /api/sync/history` retourne les sessions de l'utilisateur connecté (paginées)
- [ ] `DELETE /api/sync/data` supprime toutes les données cloud de l'utilisateur (RGPD)
- [ ] Les valeurs PII brutes ne sont jamais retournées — uniquement les types et domaines masqués
- [ ] Toutes les routes sont protégées par JwtAuthGuard (401 sans token)
- [ ] La suppression est irréversible et retourne 204

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer :**
- `apps/api/src/sync/sync.module.ts`
- `apps/api/src/sync/sync.controller.ts` — GET /api/sync/history, DELETE /api/sync/data
- `apps/api/src/sync/sync.service.ts` — getHistory(userId), deleteUserData(userId)
- `apps/api/src/sync/ports/sync.repository.ts` — interface ISyncRepository
- `apps/api/src/sync/infrastructure/prisma-sync.repository.ts`

**Patterns à respecter :**
- Clean Architecture : SyncService injecte ISyncRepository (port)
- Les PII retournées sont uniquement `{ type, destination, timestamp }` — jamais `maskedValue` (données personnelles même masquées ne doivent pas transiter inutilement)
- Pagination côté DB (limit/offset ou cursor) — pas de `findMany()` sans limite
- Importer SyncModule dans AppModule
