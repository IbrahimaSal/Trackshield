## User Story

En tant que le plugin, je veux envoyer mes détections (trackers, PII) vers l'API sous forme de batch afin qu'elles soient sauvegardées côté serveur quand Marie a activé la sync.

## Contexte

C'est le cœur de la sync cloud. Le plugin construit un `EventBatchDto` toutes les 5 secondes et le POST sur `/api/events`. Sans ce module, la synchronisation reste une coquille vide — sync-client.ts envoie des requêtes qui tombent dans le vide. Une fois ce module créé, l'AppModule doit importer EventsModule (l'item 8.1 sera résolu dans ce même ticket).

## Critères d'acceptation

- [ ] `POST /api/events` accepte un `EventBatchDto` valide et retourne 201
- [ ] Les events sont persistés en base avec l'ID de session et le timestamp
- [ ] Une requête sans JWT valide retourne 401 (route protégée)
- [ ] Un batch avec `sessionId` inconnu est rejeté avec 404
- [ ] `AppModule` importe `EventsModule` — `imports: []` est résolu
- [ ] Aucun `any` TypeScript dans le controller, service ou DTO

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer / modifier :**
- `apps/api/src/events/events.module.ts`
- `apps/api/src/events/events.controller.ts` — POST /api/events, protégé par JwtAuthGuard
- `apps/api/src/events/events.service.ts` — use case : processEventBatch
- `apps/api/src/events/ports/events.repository.ts` — interface IEventsRepository
- `apps/api/src/events/infrastructure/prisma-events.repository.ts`
- `apps/api/src/app.module.ts` — importer EventsModule (et PrismaModule si nécessaire)

**Patterns à respecter :**
- `EventBatchDto` importé depuis `@trackshield/shared-types` — ne pas le redéfinir
- `class-validator` pour valider le body entrant
- Clean Architecture : EventsService orchestre, le repository persiste
- L'idempotence est assurée côté plugin (batchId unique) — l'API stocke sans vérifier les doublons en V1

**Dépend de :** TS-001 — PrismaService · TS-002 — Module Auth
