## User Story

En tant que Thomas, je veux générer un rapport structuré sur un site audité afin de le partager avec mon client comme preuve de non-conformité RGPD.

## Contexte

La route `POST /report` retourne actuellement `{"status": "not implemented"}` avec un code 501. C'est la seule route de l'analyzer qui n'est pas implémentée. Le rapport doit contenir : score RGPD, trackers détectés, PII exposées, résumé en langage naturel, recommandations — en HTML exportable (PDF via WeasyPrint est optionnel en V1).

## Critères d'acceptation

- [ ] `POST /report` retourne un rapport structuré en JSON en moins de 5 secondes
- [ ] Le rapport contient : score RGPD (grade + valeur), liste des trackers, liste des PII (masquées), résumé en langage naturel généré automatiquement
- [ ] Les valeurs PII dans le rapport sont masquées (`j••••@gmail.com`) — jamais en clair
- [ ] Le rapport peut être sérialisé en HTML autonome (pas obligatoirement PDF en V1)
- [ ] Le résumé automatique utilise les données réelles (pas un texte statique)

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer / modifier :**
- `apps/analyzer/src/api/routes/report.py` — implémenter la route (remplacer le 501)
- `apps/analyzer/src/domain/report_generator.py` — logique de génération du résumé + structure rapport
- `apps/analyzer/src/api/schemas.py` — ajouter `ReportRequest` et `ReportResponse` (Pydantic v2)

**Patterns à respecter :**
- Clean Architecture : `report_generator.py` est dans `domain/` — 0 dépendance FastAPI
- Pydantic v2 pour tous les modèles d'entrée/sortie — pas de `dict` nu
- Le résumé en langage naturel est généré par template (f-string structurée) — pas de LLM en V1
- Mypy strict : toutes les fonctions annotées, pas de `Any`
- Réutiliser `compute_score` de `rgpd_scorer.py` pour le score

**Dépend de :** Aucune dépendance bloquante

## Hors scope de ce ticket

- Export PDF via WeasyPrint (V2 — dépendance système lourde)
- Résumé généré par LLM (V2)
- Stockage du rapport en base (NestJS — TS-005)
