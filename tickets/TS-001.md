## User Story

En tant que le système, je veux une connexion fiable à PostgreSQL afin que tous les modules de l'API puissent lire et persister les données sans gérer directement la connexion.

## Contexte

Sans PrismaService, aucun module NestJS ne peut accéder à la base de données. C'est le prérequis absolu de toute l'API — Auth, Users, Events et Sync en dépendent tous. Aujourd'hui l'AppModule est vide et rien ne peut être branché.

## Critères d'acceptation

- [ ] `PrismaService` est injectable dans n'importe quel module NestJS
- [ ] La connexion est établie au démarrage (`onModuleInit`) et fermée proprement à l'arrêt (`onModuleDestroy`)
- [ ] `enableShutdownHooks` est appelé pour éviter les fuites de connexion en production
- [ ] Aucun `any` TypeScript dans le service

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer / modifier :**
- `apps/api/src/prisma.service.ts` — service injectable qui étend `PrismaClient`

**Patterns à respecter :**
- Étendre `PrismaClient`, implémenter `OnModuleInit` et `OnModuleDestroy`
- Typage strict — pas de `any`, retour de `onModuleInit(): Promise<void>`
- Ne pas exposer Prisma en dehors de la couche infrastructure — ce service sera injecté uniquement dans les repositories (adapters), jamais dans les use cases

**Dépend de :** Aucune dépendance bloquante
