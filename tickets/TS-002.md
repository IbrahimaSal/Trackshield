## User Story

En tant que Marie, je veux que mon compte et mon historique soient protégés afin que personne d'autre ne puisse consulter mes données de navigation synchronisées.

## Contexte

Sans authentification, il est impossible de sécuriser la sync cloud. Ce module est un prérequis du module Users (inscription/connexion) et du module Sync (accès aux données personnelles). Il doit rester invisible pour Marie — elle s'authentifie une seule fois et ne le voit plus.

## Critères d'acceptation

- [ ] Un utilisateur peut obtenir un JWT valide en échangeant ses credentials
- [ ] Les routes protégées retournent 401 sans token valide
- [ ] Les tokens expirent (durée configurable via variable d'environnement)
- [ ] Aucun secret JWT n'est codé en dur — lu depuis `process.env`
- [ ] Aucun `any` TypeScript dans les guards ou strategies

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer :**
- `apps/api/src/auth/auth.module.ts` — déclare AuthService, JwtStrategy, exporte JwtAuthGuard
- `apps/api/src/auth/auth.service.ts` — validateUser, login (retourne access_token)
- `apps/api/src/auth/jwt.strategy.ts` — étend `PassportStrategy(Strategy)`, valide le payload
- `apps/api/src/auth/jwt-auth.guard.ts` — étend `AuthGuard('jwt')`

**Patterns à respecter :**
- `@nestjs/jwt` + `@nestjs/passport` + `passport-jwt`
- Clean Architecture : AuthService dans `application/`, JwtStrategy dans `infrastructure/`
- Le payload JWT contient `{ sub: userId }` uniquement — pas de données personnelles
- `JWT_SECRET` et `JWT_EXPIRES_IN` lus depuis ConfigModule (déjà dans .env.example si présent)

**Dépend de :** TS-001 — PrismaService
