## User Story

En tant que Marie, je veux voir les détections PII regroupées par valeur et destination, afin de comprendre ce qui est transmis sans être noyée sous des centaines de lignes identiques.

## Contexte

Sur une page comme X/Twitter, le player vidéo génère des dizaines de requêtes identiques vers `video.twimg.com` en streaming adaptatif. Sans déduplication, le popup affiche 150+ lignes pour la même valeur → le signal est perdu dans le bruit. La vue FluxView et la PiiBox doivent grouper les détections identiques et afficher un compteur.

## Critères d'acceptation

- [ ] Dans FluxView et PiiBox, les détections avec le même `maskedValue` + `destination` sont groupées en une seule ligne
- [ ] Un compteur `×N` s'affiche à côté des lignes dupliquées (ex: `0397••••4687 → video.twimg.com ×15`)
- [ ] L'ordre d'affichage est décroissant par nombre d'occurrences (les plus fréquentes en premier)
- [ ] Le score RGPD (et le nombre de PIIs affiché dans ScoreBlock) reste basé sur le nombre de détections uniques, pas le total brut
- [ ] Les tests des composants concernés sont mis à jour pour vérifier le regroupement

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer / modifier :**
- `apps/plugin/src/popup/views/FluxView.tsx` — grouper par `maskedValue + destination`, afficher `×N`
- `apps/plugin/src/popup/components/blocks/PiiBox.tsx` — idem pour la PiiBox
- `apps/plugin/src/popup/stores/session.store.ts` — ajouter un sélecteur `uniquePiis` (dédupliqué) pour ScoreBlock
- `apps/plugin/src/popup/views/__tests__/FluxView.spec.tsx` (ou créer) — tester le regroupement

**Patterns à respecter :**
- Déduplication côté vue (pas dans le store) — le store garde toutes les détections brutes pour l'historique
- `uniquePiis` = `Map<maskedValue+destination, { pii, count }>` calculé dans le composant
- Composants fonctionnels React uniquement

**Dépend de :** Aucune dépendance bloquante
