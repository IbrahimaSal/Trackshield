## Contexte

Le CNAME cloaking est une technique de contournement des bloqueurs de trackers : au lieu d'appeler `pixel.facebook.com` directement (facilement bloqué), le site crée un sous-domaine first-party comme `metrics.monsite.com` qui est un alias DNS (CNAME) pointant vers `pixel.facebook.com`. Du point de vue du navigateur, la requête semble first-party — elle passe les bloqueurs de domaines tiers.

C'est très répandu chez les grands médias (presse, e-commerce) qui veulent contourner les adblockers tout en restant "conformes" RGPD sur le papier. C'est aussi l'angle mort le plus sérieux de Trackshield : les autres détections (TS-017 à TS-022) deviennent aveugles face à cette technique.

## Questions ouvertes à résoudre en cadrage

1. **Résolution DNS depuis l'extension** : l'API `chrome.dns` (non standard, Manifest V3 expérimental) permet-elle de résoudre des CNAMEs ? Quelle est la disponibilité cross-browser ?
2. **Heuristiques alternatives** : peut-on détecter le CNAME cloaking sans résolution DNS — par exemple via les headers de réponse (`Server`, `X-Powered-By`, `Set-Cookie` avec domaine tiers), ou via une base de CNAMEs connus (projet "CNAME Cloaking List" de uBlock Origin) ?
3. **Base de CNAMEs connus** : existe-t-il une liste maintenue (uBlock, AdGuard, DuckDuckGo) qu'on pourrait intégrer dans `tracker-lists` ?
4. **Certitude et faux positifs** : comment ne pas accuser un sous-domaine first-party légitime (CDN, auth, API interne) d'être un tracker ?
5. **Valeur perçue** : combien de sites dans le top 1000 FR utilisent cette technique ? Est-ce que ça vaut l'effort ?

## Approches techniques à évaluer

| Approche | Avantages | Inconvénients |
|---|---|---|
| `chrome.dns.resolve()` | Détection exacte | API expérimentale, non dispo Firefox, latence |
| Liste de CNAMEs connus | Fiable sur les cas documentés, pas de latence | Liste à maintenir, angles morts sur les CNAMEs non répertoriés |
| Heuristiques headers réponse | Fonctionne sans liste | Beaucoup de faux positifs potentiels |
| Hybride liste + DNS fallback | Meilleure couverture | Complexité d'implémentation |
