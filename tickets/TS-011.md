## User Story

En tant que Marie, je veux activer ou désactiver la synchronisation cloud depuis les paramètres afin de choisir explicitement si mes données sont sauvegardées, en comprenant ce que ça implique.

## Contexte

`SettingsView.tsx` affiche "Vue en construction". C'est la vue qui matérialise le principe "Privacy by design" de Trackshield : la sync est désactivée par défaut, et Marie doit donner son consentement explicite via une modale claire avant activation. Le sync store et le flow de consentement sont déjà modélisés.

## Critères d'acceptation

- [ ] La sync est désactivée par défaut au premier lancement
- [ ] Activer la sync affiche une modale listant : quelles données sont synchronisées, où elles sont stockées (PostgreSQL · Supabase · EU)
- [ ] L'activation n'est effective qu'après confirmation explicite dans la modale
- [ ] Un lien "Supprimer toutes mes données cloud" est toujours visible (appelle DELETE /api/sync/data)
- [ ] Les préférences d'alerte par catégorie sont configurables (on/off par type : critique, avertissement, info)
- [ ] L'état du toggle est persisté dans `chrome.storage.local`

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer / modifier :**
- `apps/plugin/src/popup/views/SettingsView.tsx` — remplacer le stub

**Patterns à respecter :**
- Composant fonctionnel React, props typées
- Utiliser `useSyncStore()` pour lire/écrire l'état de sync (enabled, consentGiven)
- La modale de consentement est un composant inline (pas de lib modale externe)
- Persister l'état via `local-store.ts` (`chrome.storage.local`) après chaque modification
- La suppression des données cloud appelle `fetch` vers `DELETE /api/sync/data` avec le JWT

**Dépend de :** Aucune dépendance bloquante pour l'UI (sync.store implémenté). TS-005 pour la suppression réelle des données cloud.
