## User Story

En tant que Marie, utilisatrice non-technique, je veux voir les trackers identifiés avec un nom clair, une catégorie et une description courte de leur rôle, afin de comprendre immédiatement *qui me surveille et pourquoi* — sans avoir à chercher ce que signifie "doubleclick.net".

## Contexte

Aujourd'hui les trackers sont affichés avec leur domaine technique brut ("doubleclick.net", "pixel.facebook.com"). Pour Marie, ces noms ne signifient rien — elle ferme la popup. La cartographie "donnée → destinataire" est **la proposition de valeur différenciante de Trackshield** ; si le destinataire est illisible, toute la feature perd son sens.

Ce ticket couvre deux surfaces d'affichage :
- **Vue Flux (FluxView)** — liste des trackers détectés sur la page
- **Alertes temps réel** — notification push lors d'une détection PII

## Critères d'acceptation

### Nom affiché
- [ ] Chaque tracker connu est affiché avec son nom commercial (ex : "doubleclick.net" → **"Google Ads"**, "pixel.facebook.com" → **"Facebook Pixel"**)
- [ ] Si le tracker est inconnu du référentiel, on affiche son domaine brut — jamais rien, jamais une erreur
- [ ] Le nom technique reste accessible en sous-texte ou en tooltip (pour Thomas)

### Catégorie
- [ ] Chaque tracker est associé à une catégorie parmi : `Publicité` · `Analytics` · `Réseaux sociaux` · `Fingerprinting` · `Autre`
- [ ] La catégorie est visible sans interaction dans FluxView (pas cachée derrière un clic)
- [ ] La catégorie est incluse dans le texte de l'alerte

### Description courte
- [ ] Une description d'une phrase explique ce que fait le tracker (ex : *"Mesure vos actions pour cibler des publicités sur le réseau Google"*)
- [ ] Vocabulaire non-technique : pas de "pixel", "SDK", "beacon", "endpoint"
- [ ] Longueur max : 100 caractères par description
- [ ] La description est accessible en un geste (expand, tooltip, ou ligne secondaire dans FluxView)

### Vue Flux
- [ ] Le nom lisible remplace le domaine brut partout dans FluxView
- [ ] La catégorie est affichée visuellement (label ou badge) pour chaque tracker
- [ ] La description est accessible sans quitter la vue

### Alertes temps réel
- [ ] Le texte d'alerte utilise le nom lisible : *"Votre email vient d'être envoyé à **Facebook Pixel**"* (pas "pixel.facebook.com")
- [ ] La catégorie figure dans l'alerte : *"[Réseaux sociaux] Votre email vient d'être envoyé à Facebook Pixel"*

### Couverture du référentiel
- [ ] Minimum 30 trackers fréquents couverts au lancement (voir liste ci-dessous)
- [ ] Les trackers non couverts ne bloquent pas l'affichage — fallback domaine brut
- [ ] Le référentiel est extensible sans modifier le code de détection (fichier de données séparé)

### Qualité
- [ ] `pnpm typecheck` → 0 erreur
- [ ] `pnpm test` → tous les tests passent

## Périmètre technique

**Fichiers à créer / modifier :**
- `apps/plugin/src/background/known-trackers.ts` *(à créer)* — référentiel nom + catégorie + description, indexé par domaine
- `apps/plugin/src/background/index.ts` — enrichir chaque tracker détecté avec les données du référentiel avant de l'envoyer au store
- `packages/shared-types/src/domain/` — ajouter `displayName`, `category`, `trackerDescription` sur le type tracker si absent
- `apps/plugin/src/popup/views/FluxView.tsx` — afficher nom lisible + catégorie + description
- `apps/plugin/src/popup/views/AlertsView.tsx` — utiliser le nom lisible dans le texte des alertes

**Patterns à respecter :**
- Le référentiel est défini **dans le background**, pas dans les vues
- Les vues affichent ce qu'on leur donne — elles ne contiennent pas de logique de mapping
- Composants React fonctionnels uniquement
- Types partagés via `@trackshield/shared-types`

**Dépend de :** TS-022 (cookies tiers) — indépendant pour la partie affichage, mais le référentiel doit couvrir les trackers que TS-022 peut détecter.
