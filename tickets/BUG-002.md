## Anomalie détectée

**Check :** C1 — Contrats inter-services cassés
**Fichier(s) concerné(s) :** `apps/api/src/auth/` (controller absent)
**Commande ayant détecté le bug :**
```bash
find apps/api/src/auth -name "*.controller.ts"
grep -rn "@Post\|login\|signin" apps/api/src/auth/ --include="*.ts" | grep -v spec
```
**Sortie :**
```
apps/api/src/auth/auth.service.ts:  login(userId: string): LoginResult {
# Aucun controller HTTP trouvé
```

## Impact

L'`auth.service.ts` expose une méthode `login()` interne mais aucun controller NestJS n'expose une route HTTP `POST /auth/login`. Il est donc impossible pour le plugin ou un client externe d'obtenir un JWT. Le sync-client ne peut pas s'authentifier → la synchronisation cloud est inopérante.

## Correction attendue

- [ ] Créer `apps/api/src/auth/auth.controller.ts` avec :
  - `POST /auth/register` → créer un compte (délègue à `UsersService.createUser`)
  - `POST /auth/login` → valider email+password, retourner `{ access_token }` (délègue à `AuthService.login`)
- [ ] Ajouter le controller dans `AuthModule`
- [ ] Tester avec `curl -X POST /api/auth/login -d '{"email":"...","password":"..."}'`
- [ ] `pnpm typecheck` → 0 erreur après correction
- [ ] `pnpm test` → tous les tests passent après correction
