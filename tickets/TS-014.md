## User Story

En tant que développeur, je veux une couverture de tests suffisante sur le détecteur PII afin d'être certain qu'aucun faux négatif ne laisse passer des données personnelles sans alerte.

## Contexte

Le fichier `tests/pii-detector.test.ts` existe et contient 4 cas de test. La spécification exige ≥5 cas avec couverture corpus (SHOULD_DETECT + SHOULD_NOT_DETECT). Les zones critiques comme la détection PII requièrent une couverture de branches à 100% — un faux négatif ici est une trahison directe de la promesse produit.

## Critères d'acceptation

- [ ] Au moins 5 cas de test au total dans `tests/pii-detector.test.ts`
- [ ] Au moins 1 cas SHOULD_NOT_DETECT (faux positif évité : version semver, code postal, prix)
- [ ] Les 6 types PII couverts : EMAIL, TEL, COMPORTEMENT, ID_PUB, DEVICE, LOC
- [ ] Les valeurs masquées ne contiennent jamais la valeur brute
- [ ] Aucun `any` TypeScript dans les tests

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer / modifier :**
- `apps/plugin/tests/pii-detector.test.ts` — ajouter des cas corpus manquants

**Patterns à respecter :**
- Structure corpus TDD : `SHOULD_DETECT[]` + `SHOULD_NOT_DETECT[]` avant toute implémentation
- Tester les frontières : URL encodée (`%40` pour `@`), numéro international (`+33`), paramètre embed dans query string
- Noms de tests phrases lisibles : `it('détecte un email dans un paramètre query encodé en URL')`
- Zéro infrastructure dans les tests (pas de `chrome.*`, pas de `fetch`)

**Dépend de :** Aucune dépendance bloquante

## Hors scope de ce ticket

- Modifier la logique du détecteur PII lui-même (seulement les tests)
- Ajouter de nouveaux types PII non définis dans `@trackshield/shared-types`
- Tests d'intégration (Playwright)
