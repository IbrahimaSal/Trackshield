## User Story

En tant que développeur, je veux que chaque merge sur `main` déclenche automatiquement le déploiement afin de ne pas avoir à déployer manuellement et de réduire le risque d'oubli.

## Contexte

Le pipeline CI (`ci.yml`) existe et fonctionne. Le pipeline de déploiement (`deploy.yml`) est absent — les déploiements sont actuellement manuels. Il faut automatiser : NestJS vers Vercel, FastAPI vers Railway, et optionnellement préparer l'artefact Chrome Store.

## Critères d'acceptation

- [ ] Un merge sur `main` déclenche le déploiement de l'API NestJS sur Vercel
- [ ] Un merge sur `main` déclenche le déploiement de l'Analyzer FastAPI sur Railway
- [ ] Le déploiement ne se lance que si le pipeline CI a réussi (dépendance de job)
- [ ] Les secrets de déploiement sont lus depuis les GitHub Secrets (jamais hardcodés)
- [ ] En cas d'échec de déploiement, le job échoue visiblement (pas de `continue-on-error`)

## Périmètre technique (pour l'agent /dev)

**Fichiers à créer :**
- `.github/workflows/deploy.yml`

**Structure du pipeline :**
```yaml
on:
  push:
    branches: [main]

jobs:
  deploy-api:        # Vercel via vercel CLI ou GitHub integration
  deploy-analyzer:   # Railway via railway CLI ou dockerfile push
```

**Patterns à respecter :**
- `needs: [ci]` ou trigger conditionnel sur succès du CI avant déploiement
- Secrets GitHub : `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`, `RAILWAY_TOKEN`
- Utiliser les actions officielles (vercel/deploy-action, ou railway deploy)
- Ne pas déployer les branches feature — `main` uniquement

**Dépend de :** Aucune dépendance bloquante

## Hors scope de ce ticket

- Publication automatique sur le Chrome Web Store (processus manuel requis par Google)
- Déploiement des preview environments sur PR (V2)
- Rollback automatique (V2)
