## User Story

En tant que Marie, je veux comprendre **ce qu'on prend sur moi et pourquoi c'est un problème**, sans avoir besoin de connaître les termes techniques, afin de décider en connaissance de cause si je veux continuer à naviguer sur ce site.

## Contexte

Aujourd'hui les détections de type EMAIL/TEL/LOC sont affichées avec leur valeur masquée mais sans explication. Une adresse email masquée `mar•••@gmail.com` → transmise à `pixel.facebook.com` ne dit rien à Marie sur **pourquoi c'est grave**. Le champ `label` et `description` existent déjà dans `PiiDetection` mais ne sont pas peuplés de façon utile.

L'objectif est que chaque détection affiche un label court ("Votre adresse e-mail") et une phrase d'impact orientée conséquence concrète pour l'utilisateur.

## Principe de rédaction

- **Pas de jargon** : pas de "tracking pixel", "third-party cookie", "retargeting"
- **Conséquence concrète** : ce que Marie vivra, pas ce que le tracker fait techniquement
- **Ton neutre, pas alarmiste** : informer, pas effrayer

## Mapping label + description par type

### EMAIL
- **Label** : `Votre adresse e-mail`
- **Description** : `Permet de vous identifier sur d'autres sites et applis, même sans compte. Vous pourrez recevoir des publicités ciblées liées à cette visite.`

### TEL
- **Label** : `Votre numéro de téléphone`
- **Description** : `Peut être utilisé pour vous contacter par SMS promotionnel ou vous cibler sur WhatsApp et Instagram.`

### LOC
- **Label** : `Votre localisation`
- **Description** : `Votre position géographique est transmise. Elle peut servir à personnaliser les publicités selon votre ville ou quartier.`

## Critères d'acceptation

- [ ] Chaque détection EMAIL affiche le label "Votre adresse e-mail" et sa description dans le popup
- [ ] Chaque détection TEL affiche le label "Votre numéro de téléphone" et sa description
- [ ] Chaque détection LOC affiche le label "Votre localisation" et sa description
- [ ] Le label remplace ou complète la valeur masquée dans l'affichage (voir périmètre technique)
- [ ] Si `label` ou `description` sont absents, le composant se dégrade gracieusement (affichage actuel)
- [ ] `pnpm typecheck` → 0 erreur
- [ ] `pnpm test` → tous les tests passent

## Périmètre technique

**Fichiers à créer / modifier :**
- `apps/plugin/src/background/pii-detector.ts` — peupler `label` et `description` sur chaque `PiiDetection` produite
- `apps/plugin/src/background/known-params.ts` (ou fichier existant équivalent) — si les paramètres URL connus ont déjà un label, le propager
- `apps/plugin/src/popup/components/domain/PiiTag.tsx` ou composant dédié — afficher `label` + `description` tooltip ou ligne secondaire
- `apps/plugin/src/popup/views/FluxView.tsx` — si l'affichage doit changer pour montrer le label

**Patterns à respecter :**
- Le label et la description sont définis **dans le détecteur** (background), pas dans la vue
- La vue affiche ce qu'on lui donne — elle ne connaît pas les règles métier
- Composants React fonctionnels uniquement
- Types partagés via `@trackshield/shared-types` — `label` et `description` existent déjà dans `PiiDetection`

**Dépend de :** Aucune dépendance bloquante (label/description déjà dans le type)
